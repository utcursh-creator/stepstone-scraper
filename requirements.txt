# PINNED ON PURPOSE — do not relax these back to `>=`.
#
# These were all `>=` lower bounds (geopy had no constraint at all), so pip
# resolved "newest available" at BUILD time. Two consequences:
#   1. Each Railway redeploy could install different library versions than the
#      one before it — so identical source was not an identical runtime.
#   2. A second deployment built from this repo (the client's own Railway
#      instance) resolved a DIFFERENT dependency set than the agency's. That is
#      the classic "works on ours, not on theirs" bug, and the hardest kind to
#      diagnose precisely because the source is byte-identical.
#
# These are the versions the test suite (251 tests) passes against.
#
# patchright must stay compatible with the Docker base image
# `mcr.microsoft.com/playwright/python:v1.58.0-jammy` (see Dockerfile). If you
# bump one, bump the other in the same commit — a patchright/browser mismatch
# fails at runtime inside the container, not at build time.
#
# To upgrade deliberately: change a pin, run `pytest tests/`, and deploy while
# the scraper is IDLE (a redeploy kills any in-flight scrape).
